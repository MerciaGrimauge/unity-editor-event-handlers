# 契約別のテストケース

公開APIと実装の分岐に対応する確認項目を整理しています。期待動作の一覧であり、この表への掲載だけで実行済みとは扱いません。Unityバージョン・依存パッケージ・GUI操作を含めたすべての組み合わせの網羅を意味しません。

分類は `ディスパッチャー` がSDK非依存の管理とUnity接続、`条件` が標準条件、`ハンドラー` がAAO購読、`UI` が管理画面です。実行の結果と未検証範囲は末尾に示します。

## 登録と型の配送

| ID | 分類 | 入力・操作 | 期待動作 |
|---|---|---|---|
| REG-01 | ディスパッチャー | nullの条件 / ハンドラーを登録 | ArgumentNullException |
| REG-02 | ディスパッチャー | 空・空白ID | ArgumentException、予約枠を解放 |
| REG-03 | ディスパッチャー | Changes=None / 未知ビット | ArgumentException |
| REG-04 | ディスパッチャー | 有効なChangesの組み合わせ | 登録し、その種類にだけ配送 |
| REG-05 | ディスパッチャー | 同じ通知型へ条件を2件登録 | 2件目を拒否 |
| REG-06 | ディスパッチャー | 同じ通知型とIDへ購読を2件登録 | 2件目を拒否 |
| REG-07 | ディスパッチャー | 同じIDを別通知型で購読 | それぞれ別登録として扱う |
| REG-08 | ディスパッチャー | 型名が同じ別の型、基底/派生の通知型 | 厳密な型が異なる購読へ配送しない |
| REG-09 | ディスパッチャー | 条件プロバイダーとイベントハンドラー合計100件、101件目 | 100件を保持し次の登録を拒否 |
| REG-10 | ディスパッチャー | 無効・待機中の登録を含める | 上限の枠として数える |
| REG-11 | ディスパッチャー | ID/Changes ゲッター中に再登録 | 外側の予約も数えて上限を守る |

| REG-13 | ディスパッチャー | ゲッター例外 / 登録失敗後に別登録 | 例外伝播、予約解放、空き枠を利用可 |
| REG-14 | ディスパッチャー | 条件/購読のDisposeと再Dispose | 登録解除・枠解放、2回目は無操作 |
| REG-15 | ディスパッチャー | 別スレッドの登録/Dispose | InvalidOperationException |
| REG-16 | ディスパッチャー | 条件なしで購読、後から条件登録 | 待機し、新しい通知から実行。過去を再送しない |
| REG-17 | ディスパッチャー | 購読のない条件 | TryMatchを呼ばない |
| REG-18 | ディスパッチャー | token参照を失う | 登録は残る。自動解除しない |

## バッチと実行

| ID | 分類 | 入力・操作 | 期待動作 |
|---|---|---|---|
| RUN-01 | ディスパッチャー | 同一変更の重複 | 同じ更新でKindと全IDが同じなら1入力にまとめる |
| RUN-02 | ディスパッチャー | 同一対象で異なる親遷移 | 別入力として扱う |
| RUN-03 | ディスパッチャー | 1条件に複数購読 | TryMatchは入力ごとに1回、結果を共有 |
| RUN-04 | ディスパッチャー | 複数入力・条件と、対象を編集するイベントハンドラー | 全条件の評価が終わってからイベントハンドラー実行 |
| RUN-05 | ディスパッチャー | 単一/AND/ORの複数購読 | 一致した各購読へ逐次配送。ハンドラーの先後関係を検証条件にしない |
| RUN-06 | ディスパッチャー | 公開購読API・トークン・UI | 順序指定オプションとOrderプロパティがない。管理UIの並びを実行順として扱わない |
| RUN-07 | ディスパッチャー | 条件プロバイダーとイベントハンドラー実行中に新規登録 | 現バッチには追加せず次バッチから有効 |
| RUN-08 | ディスパッチャー | 条件プロバイダーとイベントハンドラー実行中に解除・無効化 | 後続の対象処理をスキップ |
| RUN-09 | ディスパッチャー | TryMatch=false | イベントハンドラーを実行せず期限は確認 |
| RUN-10 | ディスパッチャー | TryMatch=trueでnull参照型通知 / 無効Root | 条件プロバイダーを無効化 |
| RUN-11 | ディスパッチャー | 値型通知のdefault | Root等が有効なら通知可能 |
| RUN-12 | ディスパッチャー | 実行前にRoot破棄/移動/不適格化 | その通知を実行しない |
| RUN-13 | ディスパッチャー | イベントハンドラーが条件プロバイダーの通知の値中の参照を変更 | 後続イベントハンドラーは現在の参照状態を扱う。全階層コピーはない |
| RUN-14 | ディスパッチャー | バッチ内のBatchId、次バッチ | 同じバッチでは同値、次の処理バッチで更新 |

## 期限、結果、復元

| ID | 分類 | 入力・操作 | 期待動作 |
|---|---|---|---|
| TX-01 | ディスパッチャー | Success、期限内 | この購読の追跡済み変更を確定 |
| TX-02 | ディスパッチャー | 変更なしSkip | 次の購読へ継続 |
| TX-03 | ディスパッチャー | Context編集後にSkip | Failure扱い、復元、購読無効化 |
| TX-04 | ディスパッチャー | Failure / Cancel / 例外 / OperationCanceledException | 適切な結果へ変換、復元、購読無効化 |
| TX-05 | ディスパッチャー | default HandlerResult | Failure扱い |
| TX-06 | ディスパッチャー | 条件CheckDeadline / 戻った後の期限超過 | 条件を無効化、購読は待機 |
| TX-07 | ディスパッチャー | イベントハンドラー CheckDeadline / 戻った後の期限超過 | 復元、購読無効化 |
| TX-08 | ディスパッチャー | 複数条件プロバイダーとイベントハンドラーがそれぞれ期限内 | 独立した期限として扱い、共有予算を減らさない |
| TX-09 | ディスパッチャー | 終了済みContextを編集・CheckDeadline | InvalidOperationException |
| TX-10 | ディスパッチャー | AddComponent、Modify、CreateChild、InstantiatePrefab、SetParent、Destroyの後にFailure | 各追跡済み編集を復元 |
| TX-11 | ディスパッチャー | Prefab PropertyModificationとObject参照を編集して失敗 | 記録したOverrideと参照を復元 |
| TX-12 | ディスパッチャー | 複数イベントハンドラーの前の成功と、後の失敗 | 以前の成功と元の操作を保持し、失敗したイベントハンドラーの変更を復元 |
| TX-13 | ディスパッチャー | Root/Transform削除、Root親変更、循環親変更 | 拒否 |
| TX-14 | ディスパッチャー | 階層外/永続アセット/別シーンへの編集 | 拒否 |
| TX-15 | ディスパッチャー | AddComponent不適切型、Modify null delegate、Prefab以外の配置 | 例外、実行失敗として処理 |
| TX-16 | ディスパッチャー | 読み取りだけのイベントハンドラー、変更なしSkip | Undo追跡用コレクションを生成しない |

| TX-19 | ディスパッチャー | 全体停止後の追加バッチ | 条件評価前に戻る |
| TX-20 | ディスパッチャー | halt後のドメインリロード/再起動 | メモリ上の全体停止は解除、失敗無効化は別の寿命で保持 |
| TX-21 | ディスパッチャー | 直接書き込み/外部ファイル/非シリアライズ状態/Component副作用 | Context復元の対象外として扱う |

無限ループの強制終了は実装しません。制御が戻らないコードを同じUnityプロセス内で実行しても、deadlineによる停止を確認できません。

## 標準条件とAAO購読

| ID | 分類 | 入力・操作 | 期待動作 |
|---|---|---|---|
| AV-01 | 条件 | SDK Descriptor型なし | 両条件は登録せず、イベントハンドラーは待機 |
| AV-02 | 条件 | Descriptor付きPrefabルートの作成 | AvatarPlacedを生成、Root=Avatar |
| AV-03 | 条件 | 非アクティブAvatar | 対象に含める |
| AV-04 | 条件 | Descriptorなし/Prefab以外/通知対象がコンテナ | AvatarPlacedなし、子アバターを探索しない |
| AV-05 | 条件 | Prefab stage/preview/persistent/unloaded scene | 対象外 |
| AV-06 | 条件 | 既存アバター、シーン読込、Undo/Redo | 一括付与しない |
| AV-07 | 条件 | 通知後にシーン移動 | 通知時の対象条件と一致しなければ対象外 |
| BR-01 | 条件 | Avatar直下の作成/親変更、配下にbreast名 | 胸シェイプ通知、Root=Avatar |
| BR-02 | 条件 | 大小文字と部分一致、breast以外 | OrdinalIgnoreCaseの部分一致だけ採用 |
| BR-03 | 条件 | 非アクティブRenderer、複数Rendererの共有Mesh | 含め、同一Meshの名前走査を判定中共有 |
| BR-04 | 条件 | 対象がAvatar、Avatarの孫、親にDescriptorなし | 胸シェイプ通知なし |
| BR-05 | 条件 | Prefab以外の対象 | 条件が一致すれば対象 |
| BR-06 | 条件 | 同じバッチで同じ対象の作成/親変更 | 1回だけ検出・通知 |
| BR-07 | 条件 | Mesh null、シェイプなし、名不一致 | 該当結果を生成しない |
| BR-08 | 条件 | Mesh交換・値変更・読込・アバター内の既存の子 | それだけで既存対象を再通知しない |
| BR-09 | 条件 | 結果参照を後から編集/破棄 | 結果は検出時のIndex/Name、一時参照として扱う |
| AAO-01 | ハンドラー | AvatarPlaced、AAOなし | TraceAndOptimizeを既定設定で1つ追加 |
| AAO-02 | ハンドラー | 既存AAOあり | Skip、既存設定は維持、他購読は継続 |
| AAO-03 | ハンドラー | 新規追加後にUndo/Redo・保存 | 独立したUndo、Overrideとして保存、再付与しない |
| AAO-04 | ハンドラー | 最適化/SDK upload | この購読の処理対象外 |
